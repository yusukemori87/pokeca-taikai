# ポケカ自主大会サーチ

Twitterに散らばっているポケモンカードの自主大会情報を自動で集めて、
日付・地域・空き状況から探せる一覧サイトにする仕組みです。

コードが書けなくても動かせるように書いてあります。**上から順にやれば動きます。**

---

## 1. なぜこの作り方なのか（30秒で読める設計の説明）

自主大会を探しにくい原因はこうです。

- 主催者は **Tonamel** で大会を作る
- でも **Tonamel の検索には出ない設定（限定公開）** にしている
- なので **Twitterに貼られたURLだけが唯一の入口** になっている

ここがポイントで、「検索に出ない」だけで **URLを知っていればページは開けます**。
つまりこうすれば全部拾えます。

```
Twitter検索 ─→ ツイート本文から tonamel.com/competition/XXXX を抜き出す
                        │
                        ↓
         Tonamelの大会ページを直接開いて
         日時・会場・参加費・定員・景品を読み取る
                        │
                        ↓
                 events.json（正規化されたデータ）
                        │
                        ↓
                   一覧サイト（HTML）
```

告知画像（フライヤー）から文字を読む必要はありません。
**正確な情報は Tonamel 側から取れる**ので、Twitterは「URLの配布経路」として使うだけです。
これが精度の高さの理由です。

## 2. 必要なもの

| もの | 費用 | 用途 |
|---|---|---|
| [twitterapi.io](https://twitterapi.io/) のAPIキー | $10 で100万クレジット（有効期限なし） | Twitter検索 |
| GitHub アカウント | 無料 | 自動実行とサイト公開 |

> **なぜ公式のX APIを使わないのか**
> 2026年時点で、公式X APIの新規登録は従量課金（1ツイート読むごとに $0.005）か、
> 月$42,000〜のEnterpriseしかありません。個人の趣味サイトには現実的ではないので、
> 互換APIの twitterapi.io（約33分の1の価格）を使います。

### 実測のコスト（2026-08-04 時点）

APIの呼び出し1回（＝20件取得）あたり **約280クレジット** で計算する。

| 内訳 | 呼び出し回数 | クレジット/日 |
|---|---|---|
| キーワード検索（5クエリ × 4ページ） | 20回 | 5,600 |
| 主催者追跡（25人 × 1ページ） | 25回 | 7,000 |
| **合計** | **45回** | **約 12,600** |

$10 = 100万クレジットなので **約79日ぶん、年間およそ $46**。

**安くしたい場合**は主催者追跡を毎日ではなくローテーションにする。
`ORG_ROTATE_DAYS=3` のように設定して3日に1回ずつ回せば、
主催者追跡は 1日あたり約2,300クレジットになり、**年間$20前後**に収まる。
主催者の告知は数日以内に拾えれば実用上まず困らない。

> ⚠️ 主催者追跡を `(from:A OR from:B ...)` とまとめてはいけない。
> 1クエリの取得枠（20件/ページ）を全員で分け合う形になり、投稿の多い人に埋もれて
> 他の主催者の告知が取れなくなる。実測で、単体なら6大会取れるアカウントが
> 10人まとめると全体で4大会しか取れなかった。**必ず1人ずつ投げること。**

無料枠は1万クレジット（フル収集1回ぶん）で、カード登録なしで試せる。

> ⚠️ 無料プランは **0.2 QPS（5秒に1回）** の制限があります。
> `collect.py` は自前で5.5秒間隔を空けているので、そのままで問題ありません。
> 有料プランに上げたら環境変数 `QPS_INTERVAL` を小さくすると速くなります。

## 3. 手元で試す（5分）

```bash
pip install -r requirements.txt

# ① サンプルデータでサイトを見る（APIキー不要）
python scripts/make_sample.py
python scripts/build_site.py --sample
# → docs/index.html をブラウザで開く

# ② 実データを取る（APIキーが必要）
export TWITTERAPI_IO_KEY="ここにキーを貼る"
python scripts/collect.py
python scripts/build_site.py
```

`docs/index.html` はデータを埋め込んだ**単体で完結するファイル**です。
サーバーなしでダブルクリックするだけで開けますし、そのまま公開もできます。

## 4. 自動で毎日更新して公開する（GitHub）

1. GitHubで新しいリポジトリを作り、このフォルダの中身を全部アップロードする
2. リポジトリの **Settings → Secrets and variables → Actions → New repository secret**
   - Name: `TWITTERAPI_IO_KEY`
   - Secret: twitterapi.io で取ったキー
3. **Settings → Pages → Source** を **GitHub Actions** にする
4. **Actions** タブ →「大会情報を更新してサイトを公開」→ **Run workflow** で手動実行して確認

以降は **毎日 朝7時と夜19時（日本時間）** に自動で更新され、
`https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます。

## 5.5 キーマン（主催者）の扱い

このサイトの隠れた本体はここです。**主催者を1人登録するたびに、その人の大会は以後ずっと自動で拾えるようになります。**

`collect.py` は2回検索します。

1. **キーワード検索** —「tonamel.com × ポケカ」で広く拾う
2. **主催者追跡** — `organizers.seed.json` に登録された全員に対して `from:ハンドル tonamel.com` で検索

2があるおかげで、**「ポケカ」とも「自主大会」とも書かずに告知する主催者を取りこぼしません**。実際、常連主催者ほど「第5回◯◯杯やります」としか書かないので、ここが効きます。

キーマンを足すには `data/organizers.seed.json` に追記するだけです。

```json
{
  "handle": "deregmu_og",
  "name": "ディレグム",
  "area": "富山県",
  "region": "中部",
  "note": "富山の自主大会シーンの中心人物。「ディレグム杯EX」を主催。",
  "alt_handle": "deregmu_hobby"
}
```

`region` は `北海道・東北 / 関東 / 中部 / 近畿 / 中国・四国 / 九州・沖縄 / 全国` のどれか。

なお、**3ヶ月以内に2件以上主催している人は自動でキーマンに昇格**します。手で登録するのは「今は予定が無いけど載せておきたい人」だけで十分です。

## 5.8 いま入っている初期データについて（重要）

`data/events.json` には **2026年8月3日時点で、Twitter APIなしに検索エンジン経由で実在確認できた19件**が入っています。全てTonamelの実ページを開いて確認した本物です。ただし:

- **全て2026年8月開催。9月・10月は0件**でした
- **地域は東京9・埼玉5・神奈川1・栃木1・その他4** と関東に極端に偏っています
- **西日本は0件**でした

これは収集手法の限界であって、西日本に自主大会が無いわけではありません。理由は3つ。

1. Tonamelの大会検索・トレカの地図・bear.cool など、**主要な一覧ページは全てJavaScript描画**で、通常のHTTP取得では中身が空になる
2. **x.com は robots.txt で全面拒否**。一次告知はほぼ100%がXなので、ここが読めないと話にならない
3. 検索エンジンのインデックスが数週間遅れており、**「これから開催される大会」はまだ載っていない**

つまり、**Twitter APIを繋いだ瞬間に、この3つが全部解決します。** それが唯一のボトルネックです。

## 5.9 環境変数（運用でよく使うもの）

GitHubの **Settings → Secrets and variables → Actions → Variables** で設定すると、
ワークフローを書き換えずに挙動を変えられます。

| 変数 | 既定 | 何をするか |
|---|---|---|
| `LOOKBACK_DAYS` | 7 | 何日前までの告知ツイートを探すか。大きいほど拾えるがコスト増 |
| `MAX_PAGES_PER_QUERY` | 4 | 1クエリあたりの取得ページ数（1ページ≒20件） |
| `HORIZON_DAYS` | 95 | 何日先までの大会を掲載するか |
| `ORG_LOOKBACK_DAYS` | 14 | 主催者の投稿を何日前までさかのぼるか |
| `ORG_PAGES` | 1 | 主催者1人あたり何ページ取るか。毎日走らせるなら1で足りる |
| `SKIP_TWITTER` | 0 | `1` にすると検索を飛ばし、**前回取得できなかった大会だけ**を再取得。クレジット消費ゼロ |
| `FORCE_REFETCH` | 0 | `1` にすると取得済みも含めて**全件をTonamelから取り直して再解析**。クレジット消費ゼロ |

**手動で1回走らせたいとき**は、リポジトリの `.trigger` ファイルを適当に書き換えてpushすれば、
その場で収集が始まります（Actionsタブの「Run workflow」ボタンでも同じです）。

### 事故らないための仕組み

- **見つけた大会IDは `data/pending.json` に即保存**します。Tonamelの取得に失敗しても、
  次回 `SKIP_TWITTER=1` で再挑戦できるので、Twitterのクレジットを無駄にしません。
- **コミット段階の競合に強くしてあります。** 収集中に誰かが main を更新しても、
  リモートの最新に生成物を上書きし直して push するので、収集結果が失われません。

## 6. つまずきそうなところ

**大会は見つかるのに日付や会場が空欄になる**
Tonamelのページの書き方は主催者ごとにバラバラなので、読み取りは「よくある書式」に合わせた
ベストエフォートです。精度を上げるには生HTMLを見てパターンを足します。

```bash
SAVE_RAW_HTML=1 python scripts/collect.py
# → data/raw/ に生HTMLが溜まるので、それを見て collect.py の正規表現を足す
```

パターンを足したあとは、`FORCE_REFETCH=1` で**既存の全件を作り直せます**。
Twitterのクレジットは1も使いません。

**地域が「地域未判定」になる大会が多い**
会場名に県名が書かれていないパターンです。`collect.py` の `CITY_HINTS` に
「地名 → 都道府県」を足してください。1行足すだけで、その地名の大会が全部拾えるようになります。

```python
CITY_HINTS = {
    ...
    "矢向": "神奈川県",   # ← こうやって足す
}
```

**ヘッダに日本語を入れない**
`UA` のような HTTPヘッダに日本語を入れると、latin-1 エンコードできず**全リクエストが落ちます**。
一度これで297件を丸ごと取り逃しました。ヘッダはASCIIのみにしてください。

**拾える件数を増やしたい**
`scripts/collect.py` の `SEARCH_QUERIES` に検索式を足します。
`LOOKBACK_DAYS`（何日前までさかのぼるか）と `MAX_PAGES_PER_QUERY` も効きます。

**ポケカ以外の大会が混ざる**
`NEGATIVE_WORDS` に除外したい語を足します。

## 7. 運営上の注意（ここは真面目に）

- **ツイート本文を丸ごと転載しない。** 本サイトは日時・会場などの事実情報とリンクだけを載せる作りにしてあります。事実情報自体に著作権はありませんが、告知文の全文コピーは避けてください。
- **Tonamelへのアクセスは控えめに。** `collect.py` は1件ごとに1秒待つようにしてあります。この間隔は縮めないでください。
- **掲載を望まない主催者への窓口を用意する。** 限定公開にしているのには理由があること（身内向け、参加者数の調整など）もあります。連絡先を明記し、依頼があれば外せる状態にしておくのが安全です。除外リスト機能が必要になったら追加できます。
- **非公式であることを明記する。** サイトのフッターに既に入れてあります。
- twitterapi.io は非公式のサードパーティAPIです。X の利用規約との関係は自己責任で判断してください。公式APIに切り替える場合は `collect.py` の `search_twitter()` だけ差し替えれば動きます。
